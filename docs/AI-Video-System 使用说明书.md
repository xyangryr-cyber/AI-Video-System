 AI-Video-System 使用说明书

  这是什么

  一个 12 阶段 AI 视频制作系统。你用自然语言描述想做的视频（比如"做一个 5 分钟的黄金价格走势分析视频"），AI agent
  从写稿、配音、配乐、做图表到最终合成 MP4，全流程自动完成。你只需要在每个阶段审核结果、提修改意见、确认通过。

  第一步：环境准备

  1. 配置 API 密钥与模型

  1.1 创建 .env 文件

  在项目目录下创建 .env 文件：

  cp .env.example .env

  1.2 配置 LLM（大语言模型）

  系统通过 LiteLLM 统一调用 LLM，支持任何 OpenAI 兼容接口。.env 中填入：

  ┌──────────────────────────┬────────────────────────────────────────────────────────────────────┐
  │ 变量名                   │ 说明                                                               │
  ├──────────────────────────┼────────────────────────────────────────────────────────────────────┤
  │ OPENAI_API_KEY           │ LLM API 密钥（DeepSeek / OpenAI / 任何 OpenAI 兼容服务）           │
  │ OPENAI_API_BASE          │ API 地址（默认 https://api.openai.com，DeepSeek 填 https://api.deepseek.com） │
  │ ANTHROPIC_API_KEY        │ Claude API 密钥（如不使用可留空）                                  │
  │ ANTHROPIC_BASE_URL       │ Claude API 地址（如不使用可留空）                                  │
  │ LITELLM_API_KEY          │ LiteLLM 代理密钥（如直接调 API 可留空）                            │
  └──────────────────────────┴────────────────────────────────────────────────────────────────────┘

  示例配置（使用 DeepSeek）：

  OPENAI_API_KEY=sk-你的deepseek-key
  OPENAI_API_BASE=https://api.deepseek.com

  1.3 配置 TTS（文字转语音）

  系统支持多 TTS 厂商，按需填入对应密钥即可：

  ┌──────────────────────────────┬───────────────────────────────────────────┬──────────────────────────┐
  │ 变量名                       │ 说明                                      │ 状态                     │
  ├──────────────────────────────┼───────────────────────────────────────────┼──────────────────────────┤
  │ AZURE_TTS_API_KEY            │ Azure 认知服务 TTS                        │ 待开发（当前为 stub）    │
  │ ELEVENLABS_API_KEY           │ ElevenLabs TTS                            │ 待开发（当前为 stub）    │
  │ BYTEDANCE_TTS_API_URL        │ 字节跳动 OpenSpeech TTS — 接口地址        │ 凭证已就绪，待接入       │
  │ BYTEDANCE_TTS_APP_ID         │ 字节跳动 OpenSpeech TTS — 应用 ID         │ 凭证已就绪，待接入       │
  │ BYTEDANCE_TTS_ACCESS_TOKEN   │ 字节跳动 OpenSpeech TTS — Access Token    │ 凭证已就绪，待接入       │
  │ BYTEDANCE_TTS_SECRET_KEY     │ 字节跳动 OpenSpeech TTS — Secret Key      │ 凭证已就绪，待接入       │
  └──────────────────────────────┴───────────────────────────────────────────┴──────────────────────────┘

  字节跳动 OpenSpeech TTS —— 已验证的调用方法

  前置条件（控制台侧，缺一不可）：
  - 在火山引擎控制台开通「大模型语音合成」服务（不是"标准音色"，标准音色 BV001_streaming
    会返回 HTTP 403 / code 3001 / resource_id=volc.tts.default not granted）
  - 在「应用管理」中把 APP（即 BYTEDANCE_TTS_APP_ID）显式绑定到该服务
  - 在该 APP 下勾选授权所需音色（默认使用 zh_female_sajiaonvyou_moon_bigtts）

  请求格式（三处必须严格一致：分号认证头 / cluster / 大模型音色）：

  POST https://openspeech.bytedance.com/api/v1/tts
  Authorization: Bearer;<ACCESS_TOKEN>           ← 分号，不是空格；不保留 ${} 占位符
  Content-Type: application/json

  {
    "app": {
      "appid":   "<APP_ID>",
      "token":   "<ACCESS_TOKEN>",
      "cluster": "volcano_tts"                   ← 大模型音色仍走 volcano_tts 集群
    },
    "user":  { "uid": "ai-video-system" },
    "audio": {
      "voice_type":  "zh_female_sajiaonvyou_moon_bigtts",   ← 大模型音色（_bigtts 后缀）
      "encoding":    "mp3",
      "speed_ratio": 1.0
    },
    "request": {
      "reqid":     "<唯一请求 ID>",
      "text":      "要合成的文本",
      "operation": "query"
    }
  }

  成功判据：
  - HTTP 200
  - 响应 JSON 中 code = 3000，message = "Success"
  - data 字段为 base64 编码的 MP3，解码后头 3 字节应为 FF F3 xx（标准 MP3 帧头）

  常见失败信号：
  - HTTP 403 + code 3001 + "resource_id=volc.tts.default requested resource not granted"
    → 控制台未开通大模型 TTS 或未把 APP 绑定到该服务，与代码无关
  - HTTP 401 → 认证头格式错（很可能漏了分号或写成了 "Bearer <token>"）

  接口冒烟脚本（在项目根目录、加载 .env 后直接运行可验证连通性）：

  curl -sS -X POST "$BYTEDANCE_TTS_API_URL" \
    -H "Authorization: Bearer;$BYTEDANCE_TTS_ACCESS_TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"app\":{\"appid\":\"$BYTEDANCE_TTS_APP_ID\",\"token\":\"$BYTEDANCE_TTS_ACCESS_TOKEN\",\"cluster\":\"volcano_tts\"},\"user\":{\"uid\":\"smoke\"},\"audio\":{\"voice_type\":\"zh_female_sajiaonvyou_moon_bigtts\",\"encoding\":\"mp3\",\"speed_ratio\":1.0},\"request\":{\"reqid\":\"smoke-$(date +%s)\",\"text\":\"接口连通性测试\",\"operation\":\"query\"}}"

  最近一次实测（2026-04-26）：HTTP 200 / code 3000 / 返回 77,760 字节有效 MP3。

  注意：当前 P4 阶段后端 TTS Provider 仍为 stub，返回 mock 数据；上述凭证与调用方法已实测可用，
  等待 SPEC-D Phase-4 把 ByteDance Provider 真正接进来。

  1.4 配置模型映射（config/model_config.json）

  系统有 5 个 AI 角色，每个角色可以使用不同的模型。配置文件位于 config/model_config.json：

  ┌──────────────────────────┬──────────────────────────────────────────────────────────────┐
  │ 角色                     │ 职责                                                         │
  ├──────────────────────────┼──────────────────────────────────────────────────────────────┤
  │ intent_router_primary    │ 理解用户意图，路由到正确的操作（对话分类）                   │
  │ reviewer                 │ 审核 AI 生成的内容质量（L2 语义审查）                       │
  │ gatekeeper               │ 判断阶段门禁是否通过（决策检查）                            │
  │ producer                 │ 生成视频脚本、大纲等核心内容                                 │
  │ subtask                  │ 执行子任务（研究、验证、数据查找）                          │
  └──────────────────────────┴──────────────────────────────────────────────────────────────┘

  格式说明：模型标识符的格式是 "提供商/模型名"。LiteLLM 根据前缀路由到对应 API。

  示例 — 全部使用 DeepSeek V4 Pro：

  {
    "intent_router_primary": "openai/deepseek-v4-pro",
    "reviewer": "openai/deepseek-v4-pro",
    "gatekeeper": "openai/deepseek-v4-pro",
    "producer": "openai/deepseek-v4-pro",
    "subtask": "openai/deepseek-v4-pro"
  }

  示例 — 高低搭配（便宜模型做分类，强模型做内容）：

  {
    "intent_router_primary": "openai/gpt-4o-mini",
    "reviewer": "openai/deepseek-v4-pro",
    "gatekeeper": "openai/deepseek-v4-pro",
    "producer": "openai/deepseek-v4-pro",
    "subtask": "openai/gpt-4o-mini"
  }

  支持的前缀（取决于你用的 API）：
  - openai/    → OpenAI / DeepSeek / 任何 OpenAI 兼容接口
  - anthropic/ → Claude
  - gemini/    → Google Gemini

  修改 model_config.json 后无需重启服务 —— 系统每次调用 LLM 时重新读取配置文件。

  第二步：制作第一个视频

  创建项目

  1. 打开 http://localhost:3000，看到项目列表页
  2. 点击右上角 "+ 新建项目"
  3. 填写：
    - 标题：比如"黄金价格走势分析"
    - 描述：至少 300 字，越详细越好。包括你想讲什么观点、目标观众是谁、期望的视频风格（专业/通俗/犀利评论）
  4. 提交后自动进入 Phase 0（需求定义）

  12 个阶段走一遍

  每个阶段的操作模式都一样：AI 生成 → 你审核 → 对话修改 → 确认通过。

  ┌───────────┬──────────────────────────────────────────────────┬─────────────────────────────────────────────┐
  │   阶段    │                    AI 做什么                     │                 你要做什么                  │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P0        │ 分析你的描述，输出结构化需求（主题、类型、时长、 │ 审核 AI                                     │
  │ 需求定义  │ 平台规格）                                       │ 总结的需求对不对，不对就在对话框里说        │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P1        │ 生成 2-3                                         │ 选一个最喜欢的大纲，或让 AI                 │
  │ 内容主线  │ 个不同结构的大纲（时间线型、悬念型、痛点型）     │ 融合两个版本的优点                          │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P2        │ 写出完整旁白脚本，标注关键数据和引用来源         │ 逐段审核脚本；对某段不满意就写"把第二段改得 │
  │ 口播脚本  │                                                  │ 更口语化"                                   │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P3        │ 把脚本改成自然口播风格（专业/亲民/犀利三种风格可 │ 选择风格，对比润色前后效果                  │
  │ 脚本润色  │ 选）                                             │                                             │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P4        │ TTS 生成分段旁白音频 + 完整旁白 MP3              │ 听一遍完整音频，调整语速/音色/重录某段      │
  │ 人声旁白  │                                                  │                                             │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P5        │ 分析情绪曲线，推荐 BGM，生成"旁白+音乐"混音预览  │ 听混音效果，调整音量曲线，选/换音乐         │
  │ 背景音乐  │                                                  │                                             │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P6        │ 标注脚本中哪些位置加音效，生成最终音频           │ 先确认音效位置，再听分段效果，最后听完整音  │
  │ 音效设计  │                                                  │ 频                                          │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P7        │ 把每段脚本映射到视觉画面（数据图表/B-Roll素材）  │ 审核分镜卡片，调整镜头类型和时长            │
  │ 分镜脚本  │                                                  │                                             │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P7A       │ 获取并验证所有需要的数据、图表、图片             │ 审核"镜头×物料"对照表，调整图表参数         │
  │ 物料补充  │                                                  │                                             │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P8 关键画 │ 把所有图表/模板渲染成视频片段                    │ 查看画面预览，逐个调整                      │
  │ 面渲染    │                                                  │                                             │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P9 B-Roll │ 搜索版权免费的素材视频，下载裁剪                 │ 审核素材缩略图，换掉不满意的                │
  │ 素材      │                                                  │                                             │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P10       │ 画面+音频+字幕+转场 → 导出粗剪 MP4               │ 在播放器里看粗剪，标注要改的地方            │
  │ 粗剪合成  │                                                  │                                             │
  ├───────────┼──────────────────────────────────────────────────┼─────────────────────────────────────────────┤
  │ P11       │ 根据反馈精修，生成封面图，导出多平台版本         │ 选封面，下载 MP4 和 SRT 字幕文件            │
  │ 精剪交付  │                                                  │                                             │
  └───────────┴──────────────────────────────────────────────────┴─────────────────────────────────────────────┘

  关键交互方式

  对话框是主要操作界面。 你可以说：

  - "把开头改得更直接一点" → AI 重新生成开头
  - "第二段的数据太旧了，用 2025 年的" → AI 触发研究子任务
  - "我不喜欢这个风格" → AI 换一种风格重新生成
  - "这个数据来源可靠吗" → AI 进入事实核查流程

  推进到下一阶段： 当前阶段所有任务完成后，底部会出现 "确认进入下一阶段" 按钮，点击即可。

  回退修改： 左侧阶段导航可以点击已完成的历史阶段，但回退会使后续阶段失效（文件保留，需要重新确认）。

  当前限制和注意事项

  1. 需要稳定的网络和 API 访问——LLM 和 TTS 都依赖外部 API
  2. 单个视频成本约 $8-$15（LLM API 费用）
  3. 整个流程大约需要你 30-45 分钟的操作时间（大部分时间 AI 在后台工作）
  4. 推荐项目描述写够 300 字以上——信息越充分，AI 产出质量越高
  5. 前端工作台页面（WorkflowPage）还有部分 UI 组件是占位状态——核心对话和审核功能可用，但右侧"Agent 活动流"面板等功能可能还在完善中
  6. TTS（文字转语音）后端 Provider 尚未接入——P4 阶段的人声旁白当前为 stub（返回 mock 数据），无法生成真实音频。字节跳动 OpenSpeech TTS 的 API 凭证已配置在 .env 中，调用方法已实测通过（HTTP 200 + 有效 MP3，详见「1.3 配置 TTS」），等待 SPEC-D Phase-4 把 Provider 接进来
  7. 12 阶段流水线的 BDD 验收测试完成 9/18（SPEC-G-000 系列 + G-001/002/003），剩余 P6/P8/P10/P11 等阶段的编排层接线尚未完成——意味着部分阶段的后端调度逻辑可能不完整
  8. Docker 在中国大陆可能无法直接从 Docker Hub 拉取镜像——如果 docker compose 失败，请使用本地 .venv 方式启动
